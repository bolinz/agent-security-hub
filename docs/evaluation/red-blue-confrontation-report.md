## Validation Results (Round 2 - Red Team)

第一轮防御全部判定为"仅部分有效"。根本原因：**被评估方始终是自报数据的唯一来源，防御仅是对自报数据的二次加工，未引入外部验证闭环**。典型问题：

| Core Concern | Status | Bypass Risk |
|--------------|--------|-------------|
| 置信度 C1 "不得接受" vs 默认 L=3 机制矛盾（I≤2 时 3×2=6 仍落接受带） | Partial | 高 |
| 链式放大压分 vs 强制上调提分形成净边界博弈激励 | Partial | 高 |
| 双轨/门禁未定义"哪个数主导"，决策者可取有利口径 | Partial | 中-高 |
| 热力表 25 格逐一赋值=25 次主观判断 | Partial | 高 |
| 名义独立可被选宽松审计方/审子集/自我宣告绕过 | Partial | 中-高 |
| 模型无更新/失效机制 | Partial | 中 |

## Optimized Defenses (Round 2 - Blue Team)

核心思路：**把"可信度"从数值运算中剥离，单独作为门控层（验证等级 V0-V3）**。数值怎么算不重要，结论由"最保守口径 + 验证门控 + 确定性规则"三重锁定。

| # | Original Defense | Enhancement | New Effectiveness |
|---|------------------|-------------|-------------------|
| D1 | 强制上调 L | 拆为"默认值+结论门控"：V0 未验证→结论上限"中"、禁止"接受"；强制上调改确定性修正规则表 | High |
| D2 | 置信度 C0-C3 | 并入验证等级 V0-V3，作用于结论档位而非数值运算 | High |
| D3 | 控制缺失强制上调 | 并入确定性修正规则表，取消自由裁量 | High |
| D4 | 证据分级 E0-E3 | 合并进 V0-V3（单条数据可靠性轴向） | Medium |
| D5 | EAL 保证等级 | 重新定义：EAL=评估深度，作为结论声明上限 | High |
| D6 | 范围圈定 | 范围预注册+变更日志，事后调整须降 V | High |
| D7 | 能力清单 | I 强制锚点：每条 I 赋值必须映射到具体能力 | High |
| D8 | 控制存在性 | 证据锚定+抽查覆盖（高风险向量 100%） | Med→High |
| D9 | 指标选择 | 与 D10 合并为指标注册清单，禁止现场新增 | Medium |

## Final Consensus (Round 3)

- **All critical vulnerabilities addressed**: Yes（7 项核心问题全部被结构性方案覆盖）
- **Defenses practical to implement**: Yes（全部 10 项方案均可在纯 Markdown 约束内落地）
- **Residual risk acceptable**: Yes（Medium 残余，集中于执行纪律与 L/I 输入判断）

## Residual Risk (Medium)

1. **真实世界审计执行质量**（Med-High）：署名交叉抽查无法阻止橡皮图章/串通签名；需沿用"来源 URL+检索日期"证据惯例
2. **模型被应用超出设计边界**（Medium）：可用于非财务损失场景/安全关键系统，校准失效；适用范围应作为强制前置检查
3. **L/I 输入的方向性乐观**（Low-Med）：乐观评估者低估 L；验证闭环拦得住"明显无据"，拦不住"方向性乐观"
4. **对抗性用例集时效衰减**（Low-Med）：静态用例集需评审期限触发刷新
5. **链预注册完备性依赖人工**（Low）：漏列链腿则布尔传播不触发

## Implementation Notes（实现时须钉死的 3 个规范细节）

1. **max 决策树的"档位"方向**：`总体结论 = max(瓶颈档位, 总分档位)` 中档位取"更差"方向才符合保守主导语义，须写死输入/输出映射
2. **边界滞回的适用域**：乘积空间上 7/13/14/17-19 等不可达，"距边界 1 分内"需明确作用于 L/I 原始输入还是乘积结果
3. **V1/V2/V3 完整映射**：方案仅明确 V0，需补齐 V1-V3 各自的结论上限与证据要求
