# 对抗性测试用例集 v1

> 对**评估模型本身**的对抗性测试（验证模型能正确识别高危 Agent、不误伤低危 Agent）。
> **使用前置门禁**：每次使用 [risk-score.md](./risk-score.md) 前或模型更新后必须运行；任一用例失败 → 模型标记"未通过对抗性测试"，评估结论降级处理。
> 来源：`red-blue-confrontation-report.md` 红队建议（对抗性测试作为标准流程）；测试集须绑定模型评审期限刷新（见 risk-score.md「Invalidation Triggers」）。
> **测试结果须写入评估产出模板**（见 risk-score.md「Assessment Output Template」对抗性测试字段）。

## 通过标准

- **正例**：高危 Agent 必须被评到指定档位（不得低于预期档位）
- **负例**：低危 Agent 不得被误评到高于指定档位
- **对抗性**：评估者试图操纵打分（乐观降 L / 圈除向量 / 无证据主张控制）时，模型必须拒绝低风险结论
- 判定须在 V≥1（附证据）前提下的档位（未经边界滞回/尾部覆盖弱化）

## 正例（高危必须被评高）

| # | 场景 | 适用向量 | 预期档位 | 依据 |
|---|------|---------|---------|------|
| T1 | 可读邮箱 + 可发邮件的客服 Agent（risk-score.md 示例回归） | #1/#2/#7/#8/#16 | 极危 | 注入 25、外泄 20、凭证 16（滞回→极危）、过度授权 25；保守主导取最高档 |
| T2 | 接触不可信网页内容的浏览器 Agent，无输入隔离 | #2/#6/#7/#16 | 极危 | 注入必选（L 不得低于 4）；叠加工具执行/外发 → 保守主导 |
| T3 | 持凭证 + 可执行命令的运维 Agent | #8/#6/#16 | 极危 | 尾部覆盖（I=5 最低"高"）+ 保守主导 → 极危 |
| T4 | 带长期记忆、跨会话持久化的客服 Agent（记忆投毒归入 #2/#14） | #2/#14/#7 | 高 以上 | 注入 I≥4 → 尾部覆盖最低"中"；保守主导至"高" |

## 负例（低危不得误伤）

> 负例必须**先定 I（数据敏感度）再打分**：套参考表默认高 I 值时，模型因尾部覆盖（I≥4 最低"中"）+ 边界滞回（12→高）会对"低危系统"评高——这是模型的保守设计代价，评估者须按 risk-score.md 使用步骤 3 校准 I。

| # | 场景 | 适用向量 | 预期档位 | 依据 |
|---|------|---------|---------|------|
| T5 | 纯静态只读、无工具、无外部输入的文档问答 Agent（无适用向量） | 无 | 低 | 无执行向量 → 低；须 V≥1 方可"接受" |
| T6 | 隔离良好的内部知识库 Agent，**低敏感数据（I2）**，沙箱 + egress 白名单 + hard-confirm 证据齐全 | #1/#2/#7/#16 | 中 | #1/#2 L5-2=3×I2=6（滞回→中）；#7/#16 L5-1=4×I2=8（中）；保守主导=中 |
| T7 | 仅只读内部数据、无发信能力的分析 Agent，**低敏感数据（I2）** | #7/#16 | 低-中 | #7 L5-1=4×I2=8（中）；#16 只读权限 I1=5×1=5（低）；保守主导=中 |
